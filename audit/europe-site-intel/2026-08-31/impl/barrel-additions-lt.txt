3a. packages/schemas/src/siteintel/vocabularies/lt.ts
    `ltAsgrProvenanceColumns(field: LtAsgrValueField)` returns column names that DO NOT
    EXIST on the live service, in two independent ways:
      (i)  it inserts an underscore before the suffix (`MAX_AUK_M_TP`); the real columns
           have none (`PAGR_PASKTP`, `PAGR_PASKNR`, `PAGR_PASKD`, `PAGR_PASKTPR`);
      (ii) it is typed over `LtAsgrValueField` = the four NUMERIC fields, which carry NO
           provenance columns at all. The suffixed families exist ONLY for the four
           CLASSIFICATION fields PAGR_PASK / NAUD_BUD / FUNKC_ZON / NAUD_TIP.
    Any caller that trusts this helper queries non-existent columns and gets an ArcGIS
    400-in-a-200 body. The adapter does not call it; it uses its own measured
    `ltAsgrProvenanceColumnsMeasured()` in `ltAsgrProvider.ts`, which is unit-asserted.
    SUGGESTED FIX (schemas lane, not this one): retype the helper over the four
    classification fields and drop the underscore. That is a behaviour change to an L0
    module, so it wants its own lane; it is NOT a canonical-model change (E4 control 3 is
    not engaged — no entity, field or abstraction moves).

3b. packages/site-parcel-data/src/sourceRegistry/lt.ts
    The `lt-vtpsi-asgr-mapserver` row's `dataset` string says the four numerics come
    "with per-value provenance columns (*_TP/*_NR/*_D/*_TPR) + PILN completeness flag".
    Measured 2026-09-01, both halves are wrong: the provenance families belong to the
    classification fields (see 3a), and PILN is non-null on 0 of 175,570 polygons
    nationally (as are ATN_DOK and PRIORIT). The lane file
    lanes/netherlands-poland-lithuania-estonia.md §LT-1 carries the same claim and should be
    corrected in the same pass. Suggested replacement text for the row's dataset field:

      'ASGR layer 0, ArcGIS-REST dialect, LKS-94/EPSG:3346 — MAX_AUK_M / MAX_INTENS /
       MAX_TANKIS / MIN_APZELD (NO per-value provenance on these), plus PAGR_PASK /
       NAUD_BUD / FUNKC_ZON / NAUD_TIP which DO carry per-value provenance columns
       (<FIELD>TP/<FIELD>NR/<FIELD>D/<FIELD>TPR, no underscore). PILN/ATN_DOK/PRIORIT are
       declared but nationally unpopulated (0 non-null of 175,570, measured 2026-09-01).'

    And the same row's probe log should gain the 2026-09-01 re-measurement:
    175,570 polygons; MAX_AUK_M non-null 31,960 (18.2%); MAX_INTENS 23,932 (13.6%);
    MAX_TANKIS 30,393; 141,020 (80.3%) carry no numeric regulation at all.
