## §1 — Scope

**Covers.** The engineering contract for `@pryzm/auto-dimension` — a pure L2 deterministic engine that consumes an element snapshot for one level and returns a complete, deduplicated, stacked, QA-validated `DimensionString[]` (+ an `AutoDimReport`). Data structures, per-stage I/O contracts, the `DimensionString` output mapping, determinism/tie-break rules, the edge-case catalogue, and the phased plan.

**Does NOT cover.** The `DimensionString` schema itself (owned by `packages/schemas/annotation/dimension.ts`, L0 — reused, not modified); `evaluateDimensions` / `PlanViewAnnotationRenderer` (geometry-kernel L4 render half — unchanged); the sheet composition + PDF export (C24 / C29); force-directed placement (explicitly out of scope, C56 §1.5); curved-wall radius dimensioning and grids/columns/sections (P4 — sketched here, specified when picked up).

---

## §2 — Invariants (engineering — see C56 §1 for the normative set)

- **INV-1 Determinism.** Same snapshot → byte-identical `DimensionString[]` (C56 §1.1). No AI/ML/LLM, no `Math.random`/`Date.now`, no floating tie-breaks. Every order is total with a ULID `id` final comparator.
- **INV-2 Purity.** The package imports no THREE, no DOM, no I/O, no store/bus/renderer, no RNG. Only `@opentelemetry/api` is allowed (spans). It is a DTO→DTO function (C56 §1.4).
- **INV-3 Completeness.** Output satisfies DI-1…DI-6 (C56 §1.3): overall dims exist; every opening located + sized; every wall break ticked; no distance dimensioned twice; no avoidable overlap; QA **surfaces** any incompleteness as a non-blocking `AutoDimReport.warning` (no silent omission — the hard-reject `errors` channel is deferred, ADR-0119).
- **INV-4 Liveness.** Emitted strings carry element+anchor `DimensionReference`s (not raw points) so they re-evaluate on element move.
- **INV-5 Executor-only mutation.** The engine emits data; only the L5 `applyAutoDimensions` executor dispatches through a command path — the composite `CreateManyAnnotationsCommand` (RENDER sink, ADR-0119) — inside one `runBatch` (one undo, C56 §1.4).
- **INV-6 Observability.** Every exported function opens a `pryzm.autodim.*` OTel span (C56 §1.7, P8).

### §3.2 — New engine types (pure)

```ts
type PtXZ = { x: number; z: number };                // metres, plan XZ

interface DimWall { id: string; a: PtXZ; b: PtXZ; thickness: number; systemTypeId?: string; levelId: string; }

interface WallRun {                                  // one maximal collinear end-to-end run
  id: string;                                        // `run:${sortedMemberIds.join('+')}` (deterministic)
  axisDir: PtXZ;                                      // canonicalised unit direction (§6)
  members: string[];                                 // wall ids in along-axis order
  nodes: PtXZ[];                                      // ordered junction points (chain ticks)
  isExterior: boolean;                               // member of the perimeter ring?
  facade?: 'N' | 'S' | 'E' | 'W' | string;
}

interface OpeningRef {                               // opening projected onto its run axis
  id: string; kind: 'door' | 'window';
  hostWallId: string; runId: string;
  s0: number; s1: number;                            // near/far station along run (metres)
  width: number;
}

interface PlannedString {                            // planned, pre-placement
  kind: DimensionKind; autoMode: DimensionAutoMode;
  refs: DimensionReference[];                        // element+anchor (stays live, INV-4)
  axisId: string;                                    // stacking group
  orientation: DimOrientation;
  stationSpan: [number, number];                     // along-axis [start,end] for overlap tests
  priority: number;                                  // rank (overall > exterior-chain > opening-chain > …)
}

interface PlacementRecord { axisId: string; side: 1 | -1; rows: PlannedString[][]; rowOffsetsMm: number[]; }

interface AutoDimResult { strings: DimensionString[]; report: AutoDimReport; }
// ADR-0119: non-blocking `warnings` (not a hard-reject `errors` channel — deferred to P2).
interface AutoDimReport { coverage: {...}; warnings: ValidationWarning[]; skipped: { id: string; reason: string }[]; }

interface AutoDimSnapshot {                           // the executor gathers this from the stores
  walls: DimWall[]; doors: Door[]; windows: Window[]; rooms?: DetectedRoom[]; levelId: string;
}
interface AutoDimOptions { styleTable: DimStyleTable; idFactory?: () => string; modes?: DimensionAutoMode[]; }
```

`refs` uses the **element+anchor** model deliberately (INV-4). Raw-point sinks (`dimension.create` `points: Vec3[]`) are reached by running the string through `evaluateDimensions` in the executor.

## §4 — Algorithm (the 8 stages)

Entry: `planAutoDimensions(snapshot, opts) → AutoDimResult` (OTel root span `pryzm.autodim.plan`). Full grounded pseudocode: spike §11. Per-stage I/O contract:

| Stage | Input | Output | Contract |
|---|---|---|---|
| **1 — graph + perimeter** (`pryzm.autodim.graph`) | sorted `DimWall[]` | `{ junctions, graph, perimeter, rooms }` | `junctions = detectJunctions(walls, {band:0.20})`; `graph` = nodes(=junction points) + edges(=wall segments); `perimeter = computeTopology(buildPureWallGraph(walls)).outerFacePolygon`; `rooms` (P3). Nodes/edges MUST come from the ADR-0055 P1 graph so ticks == miters. |
| **2 — segmentation** (`pryzm.autodim.segment`) | walls | `openingsByWall: Map<wallId, span[]>` | `getOccupiedSpans(wall)` → openings sorted by along-wall metric offset; each wall's `[0,length]` sliced into alternating pier/opening segments. Offsets are left-edge metric offsets along `baseLine[0]→[1]` (not parametric `t`) — compose directly. |
| **3 — opening analysis** (`pryzm.autodim.segment` child) | `openingsByWall`, runs | `OpeningRef[]` | lift each opening from host-wall local axis to the run's shared axis: endpoints `a+unit(b−a)·off`, `a+unit(b−a)·(off+w)`; project onto `WallRun.axisDir` → `[s0,s1]`. Corner windows clamp `s1` to run end. |
| **4 — chain planning** (`pryzm.autodim.chain`) | graph, runs, `openingsByWall`, rooms | `PlannedString[]` | ranked planners (see §4.1); collinear runs via union-find (§4.2). |
| **5 — chain geometry** (`pryzm.autodim.resolve`) | `PlannedString[]`, runs, `openingsByWall` | ticks + refs per string | establish run datum (origin = first node, `axisDir` canonical); collect ticks (junction nodes + opening `s0/s1`); sort ascending; dedupe within `EPSILON_M=0.001`; emit consecutive `[tick_i,tick_{i+1}]` segments; assign element+anchor refs. |
| **6 — placement** (`pryzm.autodim.place`) | `PlannedString[]` grouped by axis, perimeter | `PlacementRecord[]` | side = outward normal (`leftPerp(axisDir)` signed away from `polygonCentroid`); rows stacked by rank outward (row 0 = opening chain nearest geometry, top = overall); `offsetMm = baseOffsetMm + rowIndex·rowSpacingMm` from the injected style table; order by `(axisId,rowIndex,stationStart,id)`. |
| **7 — conflicts** (`pryzm.autodim.conflict`) | placed strings, walls, spatial index | resolved strings | dedupe (DR-1/DR-2), merge tiny/zero (`<MIN_OPENING_M=0.05`), resolve text overlap (bump row, bounded), resolve geometry crossing (push out, bounded). See §4.3. |
| **8 — QA** (`pryzm.autodim.qa`) | resolved strings, snapshot, perimeter, runs | `ValidationError[]` | QA-1…QA-6 (§4.4). Never throws; records errors. |

Final: `strings = planned.map(toDimensionString(isAutoGenerated:true, autoMode))`, then `stableSort` by `(axisId, rowIndex, stationStart, id)`.

### §4.1 — Stage-4 string classes (rank → outer→inner stack order)

| Rank | Class | `kind` / `autoMode` | Rule |
|---|---|---|---|
| 1 | Overall building | `overall` | one horizontal + one vertical across the perimeter AABB; refs = the two extreme corner walls' `start`/`end`. Once per axis. |
| 2 | Exterior wall-chain | `linear-chain` / `set-out` | per perimeter façade run: chain ticking every junction node + every opening edge along the run. |
| 3 | Opening chain | `linear-chain` | per run with ≥1 opening: pier–opening–pier station chain (subset of exterior chain when coincident → deduped Stage-7). |
| 4 (P3) | Interior room chain | `room-bounding` | per detected room: overall X/Z of the room ring; later wall-to-wall internal running dims. |
| 5 | Per-element fallback | `linear-element` | ONLY for walls/openings covered by no chain (free-standing partitions). Prevents silent omission. |

### §4.2 — Collinear run grouping (Stage-4 pre-pass)

Union-find over adjacent wall pairs sharing a `detectJunctions` node: two walls join a run iff parallel within θ (15° gate, reused from `_resolveParallelWallDim`), collinear within the perpendicular band (`extensionCandidate` line test), end-to-end adjacent, and NOT merged across a foreign T-attacher (`notThroughForeignJunction`). Members ordered by station; `markExterior` by membership in `outerFacePolygon` edges.

### §4.3 — Stage-7 conflict rules (all deterministic; merge/reposition, never drop-silently)

| Conflict | Detection | Resolution |
|---|---|---|
| Duplicate (DR-1/DR-2) | same `(axisId, stationSpan)` within `EPSILON_M`, same orientation | keep higher rank; drop lower (tiebreak `id`). |
| Zero/tiny length | `|stationSpan| < MIN_OPENING_M` | drop tick; merge neighbours into one segment. |
| Overlapping text | 1-D interval overlap of label boxes (label width from unit-format digit count — deterministic, no font metrics) | bump lower-rank string to next row (bounded); if still overlapping at max rows, accept + log. |
| Stack collision (axes cross) | `intersectLines` between perpendicular dim lines | perpendicular axes stack on different sides by construction; else shorten `witness.extension` at crossing. |
| Crossing geometry | dim line intersects a wall footprint (spatial-index broad-phase) | push whole stack out one `rowSpacingMm` until clear (bounded). |
| Redundant overall | overall == sum of a complete chain within tolerance | keep both (architect convention); flag `chainCloses:true`. |

### §4.4 — Stage-8 QA rules (→ `AutoDimReport.warnings`; never throws)

> **Amendment (ADR-0119, 2026-07-07).** QA records **non-blocking `warnings`**, not a hard-reject `errors` channel (matching the shipped `AutoDimReport { warnings, skipped }` and the "surface, don't silently omit" intent — C24.1 §1.3). A hard-`errors` reject + the QA-2 run-partition detection below are **deferred to P2** (conflict/stacking).

- **QA-1** every door/window appears in ≥1 emitted string → else `opening-undimensioned` (warning).
- **QA-2** *(deferred to P2)* each run's ticks partition `[0,runLength]` with no gap/overlap > `EPSILON_M` → `chain-gap` / `chain-overlap`.
- **QA-3** each `overall` value == run/perimeter extent within 0.5% → else `overall-mismatch` (warning).
- **QA-4** post-Stage-7 re-check: no duplicates, no zero-length.
- **QA-5** `outerFacePolygon` is a closed simple ring (`RoomPolygonUtils.isSimple`) → else `open-perimeter` (warning), fall back to per-run overalls.
- **QA-6** (test-only) running twice on the same input yields a byte-identical `DimensionString[]`.

## §5 — API surface

```ts
// @pryzm/auto-dimension (L2, pure)
export function planAutoDimensions(snapshot: AutoDimSnapshot, opts: AutoDimOptions): AutoDimResult;

// registry of pure string-planners (Stage-4) — pipeline (Stages 5-8) is planner-agnostic
export interface StringPlanner { plan(snapshot: AutoDimSnapshot, graph: WallGraph): PlannedString[]; }
export function registerPlanner(p: StringPlanner): void;   // WallRunPlanner, OpeningChainPlanner, RoomChainPlanner, … (later GridPlanner/ColumnPlanner/SectionPlanner)
```

```ts
// apps/editor (L5, impure) — the ONLY command caller
function applyAutoDimensions(runtime): number {
  // span: pryzm.autodim.apply  (attrs: wall_count, string_count, annotation_count, error_count)
  const snapshot = gatherSnapshot(runtime, levelId);            // WallStore + embedded C15 openings
  const { strings, report } = planAutoDimensions(snapshot, { viewId, levelId });
  // ADR-0119 RENDER sink: adapt DimensionString[] → 'linear-dim' AnnotationElement[]
  // (via evaluateDimensions) and write the SET to the SUBSYSTEM annotationStore the
  // plan renderer reads, as ONE composite command = ONE undo (C11, C56 §1.4).
  const annotations = dimensionStringsToLinearDimAnnotations(strings, evalSnapshot, viewId);
  batchCoordinator.runBatch(() =>
    window.commandManager.execute(new CreateManyAnnotationsCommand(annotations)));
  surfaceReport(report);                                        // coverage + warnings (no silent omission)
  return annotations.length;
}
```

> **Amendment (ADR-0119, 2026-07-07).** The prior sketch dispatched `bus.executeCommand('dimension.createMany', …)`, which writes the `DimensionStore` that `PlanViewAnnotationRenderer` **never reads** — so nothing rendered. The **RENDER sink** is the subsystem `annotationStore` `'linear-dim'` path via a composite `CreateManyAnnotationsCommand` on the `CommandManager` (the subsystem store is not a CQRS `Store` in the bus `storesProvider`, so its patch-routed undo is owned by the legacy command protocol — the same path the working `LinearDimensionAnnotationTool` uses). `dimension.createMany`/`DimensionStore` are retained for **non-rendered** consumers (schedules/take-off/export), not rendering.

Output mapping: each `PlannedString` → `DimensionString { kind, autoMode, references: refs, offsetMm, orientation, arrowheads:'tick', isAutoGenerated:true }`. The executor resolves each to world points via `evaluateDimensions` and adapts to a `'linear-dim'` `AnnotationElement` at the sink.

## §6 — Determinism / tie-break rules

1. Sort walls once at entry by `(levelId, minX, minZ, id)` (ULID final tiebreak) — makes the order-dependent `detectJunctions` clustering reproducible.
2. Canonicalise `axisDir`: `axisDir.x > 0`, or `axisDir.z > 0` when `x ≈ 0` — never dependent on member insertion order.
3. Every `sort`/`min`/`max` ends in an explicit `id` comparator; never trust `Set`/`Map` iteration order (collect then sort).
4. Dimension ids via a caller-supplied `idFactory` (default monotonic); positional stability guaranteed by the Stage-8 output sort.
5. No wall-clock / RNG. Fixed-epsilon rounding (`EPSILON_M = 0.001`, mm rounding).
6. Byte-identical re-run asserted by QA-6.

## §7 — Edge-case catalogue (see spike §13 for full source grounding)

| Case | Handling |
|---|---|
| L-shaped plan | two perpendicular runs, each dimmed independently; overall = perimeter AABB; shared corner node = one tick (deduped Stage-5). |
| T-intersection | `detectJunctions` classifies T; through-wall = one run, stem = separate run terminating at the passthrough foot (`notThroughForeignJunction` guard). |
| Angled / non-orthogonal | runs use `axisDir` (not world X/Z); chain measures true length (`orientation:'aligned'`); overall still AABB. |
| Multiple adjacent openings | Stage-2 alternating pier/opening slices → pier–door–pier–window–pier ticks in one chain. |
| Tiny fragments / stubs | `detectJunctions` flags degenerate walls `invalid`; engine skips them; sub-`MIN_OPENING_M` slivers merged (Stage-7). |
| Double doors | one opening span → one width dim; leaf split not dimensioned. |
| Corner windows | Stage-3 clamps `s1` to run end (`clampToWall`); each façade shows its portion. |
| Parallel chains (cavity/party wall) | two runs on parallel axes, each stacks its own side; perpendicular gap = single cross-tie. |
| X / Y joins | `detectJunctions` handles natively; each arm its own run; shared node one tick. |
| Curved walls | **P4** — tessellate to polyline first; dim chord + radius (`kind:'radius'`). Out of P1–P3. |

## §8 — Conformance tests

- Determinism (QA-6): `planAutoDimensions` twice on the same snapshot → deep-equal `DimensionString[]` (the `check-autodim-determinism.ts` gate).
- Purity: `check-autodim-purity.ts` — no THREE/DOM/store/bus/renderer/RNG import in the package.
- Coverage (QA-1…QA-4): on the reference rectangular + L plans, every opening located+sized, chains partition each run with no gap/overlap, each overall within 0.5%, no duplicates/zero-length.
- One-undo: the executor dispatches inside exactly one `runBatch` (`check-autodim-executor-onebatch.ts`).
- OTel: every exported function opens a `pryzm.autodim.*` span (`check-autodim-otel-spans.ts`).

## §9 — Performance targets (C10)

Target **O(n log n)** overall (n=walls, m=openings). The as-shipped `detectJunctions` clustering is `O(n²)` — the only super-linear hot spot, bounded per-level (≤ hundreds), reducible via the existing `SpatialGrid`/`TopologySpatialIndex` broad-phase (Stage-1 pre-bucket + Stage-7 crossing) — an optimisation, not a P1 correctness requirement. Segmentation `O(m log m)`, run grouping near-linear via graph adjacency, tick resolution `O((n+m) log(n+m))`, placement/conflict `O(K log K)`. See spike §12.

## §10 — Phased plan

| Phase | Scope | Exit |
|---|---|---|
| **P1 — MVP** | exterior wall-chain + located/sized openings on rectangular + L plans; overall (rank 1) + exterior chain (rank 2) + opening chain (rank 3); single-row stacking; `dimension.createMany` verb. | on any rect/L plan: overall + one exterior chain per façade with every opening located; QA-1/2/3 pass; deterministic re-run byte-identical. |
| **P2 — Conflict + stacking** | multi-row stacking, text-overlap bump, geometry-crossing push, dedupe (DR-1/DR-2), tiny-fragment merge; angled + T + parallel-chain edge cases; spatial-index broad-phase. | dense plans produce non-overlapping, non-duplicated stacks; QA-4 passes. |
| **P3 — Interior rooms** | room-bounding chains + wall-to-wall internal running dims via `computeTopology.rooms`. | every detected room dimmed; matches C24.1 `room-bounding` coverage. |
| **P4 — Documentation core** | grids, columns, sections, elevations (extend `autoMode`); extract shared pure `planar-topology` core; curtain-wall panels; curved-wall chords/radii. | walls/doors/windows/rooms/grids/columns auto-dimmed across plan/section/elevation — AutoDimension is one node in the C24.1 documentation core. |
