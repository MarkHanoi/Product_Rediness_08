## REGION HEADLINE — read this first

**This is the world capital of Type-A envelope geometry.** The census verdict is blunt:
*"the Nordic-Baltic region is the world capital of Type-A envelope geometry — DK, EE, LT, IS serve
building-field polygons today, keyless; SE has it gated, NO has it render-only, FI has it
modelled. Only LV lacks the geometry axis entirely"* (`census-nordic-baltic.md`, Lane synthesis).
Four countries publish the **drawn permitted footprint as machine-readable features** — the exact
thing the founder's §8 says never to recompute: *"Never calculate what the government already
publishes as geometry."*

**One critical honesty caveat that governs the whole region.** The *composed legal envelope
determination* is still state-served NOWHERE — that is PRYZM's IP, holding 21/21 across Europe
(memory `europe-e5-reuse-verdict`; E5-DATA-REUSE-REPORT). What the four countries serve is the
**building-field polygon (Type A geometry) plus the numeric parameters** — the P-slot and much of
the V-slot as data. PRYZM's job is to CONSUME that and compose `byggefelt ∩ height ∩ coverage ∩
restrictions` (STR §8). So "consume not build" means consume the *inputs*; the intersection and the
refusal logic are still ours.

**Where the money is:** Denmark already draws end-to-end and is the exemplar. Estonia, Lithuania,
Iceland serve the same class of geometry keyless — the gap there is a small **consume-join**, not a
rule-pack build. Sweden/Norway/Finland have the geometry but behind a free-registration gate, an
agreement gate, or a not-yet-open channel. Latvia has no geometry axis but the cleanest licence
(CC0) and a clean text-extraction target. Great Britain is the honest exception: **L7 discretionary,
no by-right envelope exists to draw — the deliverable is a range, never a number.** Ireland is
structured-zoning + part-discretionary — the WHERE is served, the HOW-MUCH is in PDFs.

  - **The binding-field obligation (`bygkunifelt = true`).** A binding byggefelt is a **minimum**
    ("byggeri kun i felt" — you must build inside it), the OPPOSITE of a maximum; drawing it as
    merely permitted UNDERSTATES the obligation. The frozen L0 `BuildableEnvelope` schema carries
    `footprintIsUpperBound` (the MAX side) but has **no `footprintIsRequired`** field. Today the
    distinction is typed correctly in the package-local `dkByggefeltBinding.ts` + recorded as named
    debt `DK_BYGGEFELT_OBLIGATION_OWED`; the interim ships the binding field down the same geometry
    path with a caveat (`lane-dk-binding.md` §2). Gap: **mint `BuildableEnvelope.footprintIsRequired`
    via a superseding ADR over C58 §2.4** — US (build) + FOUNDER (the ADR sign-off).
  - **The `det skrå højdegrænseplan` (BR18 byggeret inclined plane, height ≤ 1.4 × distance to
    naboskel/vej).** THE canonical Danish inclined plane, and it is the binding height law near
    boundaries where a lokalplan is silent — yet **zero repo hits**; the flat `maxbygnhjd` prism can
    OVERSTATE there (matrix-north C4-DK, GAP twice). Gap: (a) extract the rule from BR18 — US; and
    (b) the kernel primitive — an **inclined-plane / height-field top** — which the schema cannot
    represent today (prisms only) — US (build, shared with DE §6 Abstandsflächen).
  - **The byggelinjer WFS feed itself.** The offset machinery is shipped and engine-wired; the
    missing piece is the separate byggelinjer dataset feed (schema not yet verified) — DATA (source
    the WFS) (matrix-north C1-DK, "Data only").
  - **BR18 boundary-distance (naboskel) extraction** — the plain-inset `setback` kind already
    exists; the rule was simply never extracted from BR18 (matrix-north C2-DK, "cheapest cell") — US.
- **EFFORT:** DK is **DONE for the by-right case** — days, not weeks, for each residual. The single

## CROSS-REGION SYNTHESIS FOR THE FOUNDER

**1. The cheapest wins are CONSUME-joins, not rule-pack builds.** Estonia, Lithuania and Iceland
each serve the byggefelt-class geometry keyless, live, today. The work is a small adapter join
(the EE join is the template) plus honest refusal where the polygon is absent — days each, not
weeks. Denmark proves the pattern end-to-end. This is the founder's §8 doctrine paying off:
*"Never calculate what the government already publishes as geometry."*

**2. Three countries are one credential away.** Sweden (NGP free registration), Norway (Norge
digitalt agreement), Finland (Ryhti data-permit) all have the Type-A geometry — the blocker is a
FOUNDER signature/registration + a credential, not engineering. Ranked by ease: **SE (free reg) >
FI (data-permit) > NO (agreement).** Each converts a large plan corpus from "compile parameters" or
"catalogue" to "consume geometry" in one administrative step.

**3. Two genuinely shared engineering primitives unblock the region's hard cases:**
   - the **inclined-plane / height-field top** (Denmark's `skrå højdegrænseplan`, Germany §6, and
     the L4 "Shaped" legend the Nordics need for solar planes) — the schema is prisms-only today;
   - the **polygon-difference kernel op (A ∖ B)** (Sweden's prickmark = parcel minus no-build
     strips) — the kernel ships intersection + union only.
   Both are named costed gaps in `matrix-north.md`. Building them once serves several countries.

**4. One schema field is owed, with a founder ADR:** `BuildableEnvelope.footprintIsRequired` — the
MIN/binding side of a byggefelt (`bygkunifelt = true`). Denmark hits it live; drawing a binding
field as merely permitted UNDERSTATES the obligation (`lane-dk-binding.md`). Until the ADR mints it,
the obligation half lives in a package-local type + a named-debt marker (honest, not faked).

**5. Latvia and Ireland are text-extraction plays, not geometry plays.** Both serve the WHERE
(zoning geometry + unified codes / state parcels) cleanly and openly; both keep the HOW-MUCH in
legal text (LV: TIAN HTML on likumi.lv) or PDF (IE: development-plan standards). A provenance-first
extractor keyed on the unified zone code is the pattern for both — reusable, and exactly the
NREL-COMPASS / Catala accelerator territory the E5 report flagged.

by-right envelope in law, so the deliverable is a **range with a stated basis, never a number**. The
providers already refuse correctly. Building the range engine + the 108-dataset constraint
