## 1. The two findings this ledger exists to surface

Building the table surfaced two defects that neither the writer census nor the reader census could
see alone — they are only visible when the two columns sit side by side.

**`sitsOn` is WRITE-ONLY.** It is the most-written edge in the entire graph — nearly every element
kind emits it on creation (slab, roof, stair, column, beam, furniture, handrail, lighting,
plumbing, lift) — and the grep found **no typed reader anywhere in production**. Every write, no
reader. It is also one of the two families that a pre-graph snapshot **permanently loses**
(EV-04 §3), so the repo is carefully persisting, and carefully losing, an edge nothing consumes.

**`contains` is READ-ONLY.** Two production surfaces read it — `WorldModelAdapter.ts:152` (the AI
world model) and `HierarchyTreePanel.ts:541` (the UI tree) — and EV-04 established it has **no
first-party writer**; it is populated only by IFC import. So on any project not imported from IFC,
both surfaces ask a question that is always answered "nothing", and **cannot distinguish that from
"this room contains nothing"**. That is this repo's signature defect appearing in a new place.

These are inverse failures of the same kind: **an edge is only real when a writer and a reader
agree it exists.** Counting writers alone (EV-04) graded `sitsOn` as healthy coverage. It is not.

## 3. Priority order, derived from the table rather than asserted

The founder's brief names five first-priority relationships. The ledger sharpens *why* each one,
and reorders two:

1. **`connectedTo`** — has a writer and two readers already, and is **not rebuilt**, so it is lost
   on every pre-graph snapshot. CONNECT-3 (junction retention, in flight) hands it a deterministic
   writer. Highest value: the machinery on both sides already exists.
2. **`sitsOn`** — needs a **reader**, not a writer. The write side is the most complete in the
   graph. Give the level/containment query a typed consumer and ten kinds become queryable at once.
3. **`contains`** — needs a **writer**. Two production surfaces are already asking.
4. **`hosts` / `boundedBy`** — healthy; the work here is *keeping* them healthy under mutation,
   which is Phase 6, not Phase 5.
5. **`supports`** — extend beyond beams (slab→wall is declared and never written).

**The rebuild gap is the cross-cutting item**: `_rebuildSemanticGraph` regenerates 5 of 25 types,
so `sitsOn`, `supports`, `connectedTo`, and both vertical-circulation edges are **persist-or-lose**.
Widening the rebuild is a contained change in a function that already exists, and it protects four
of the five priority rows at once.

## 4. What this ledger does NOT establish

- **Mutation-update on MOVE is UNPROVEN for every row.** Delete is measured (EV-03: cascade removes
  edges for every kind *except wall*). Whether a move preserves, updates or strands an edge was not
  measured — and for `boundedBy` after a room-boundary change it is the row most likely to be wrong,
  given EV-03's finding that room identity survives only by centroid proximity.
- **Reader counts are grep-derived**, so a reader reached only through dynamic dispatch or a
  `getAll()` scan would not appear. `WorldModelAdapter:310` and `RelationshipExplorerPanel:186`
  read *all* relationships untyped — they are not counted as typed readers above, deliberately,
  because "something enumerates every edge" does not mean an edge family is consumed.
- **No runtime probe was executed.** Every claim is source-level. A writer that exists but is
  never reached at runtime would still read as ✅ here — the exact hazard CA-21 was built to catch
  for verbs, and which the graph has no equivalent of yet.
